## Project Context for Gemini Agents

This document provides context for the BSAN project to guide future Gemini agents.

### Benchmark Pipeline & Visualization

The benchmark visualization page is generated by the `.github/workflows/bench.yml` workflow and deployed to GitHub Pages.

**Data Flow:**

1.  The `bench.yml` workflow is triggered on pushes to `main`.
2.  The `build` job runs benchmarks on multiple architectures using `./xb bench`. The raw JSON results from `hyperfine` are stored as artifacts.
3.  The `process-and-deploy` job is the core of the data processing. It performs the following steps:
    a. Checks out the `main` branch to `./main` and the `gh-pages` branch to `./gh-pages`.
    b. Runs `prepare-data.js` to aggregate the raw benchmark artifacts from the current run into a single `dist/data.js` file. This file contains the `window.benchmarkData` object.
    c. Runs `update-history.js` which:
        i. Reads `dist/data.js` for the current run's data.
        ii. Reads `gh-pages/history.js` for the historical data.
        iii. Merges them, appending the current run's data to the history object under the current commit SHA.
        iv. Writes the result to `dist/history.js`. This file contains the `window.benchmarkHistory` object.
    d. The entire `./main/bsan-script/bench` directory (containing the UI, `data.js`, and `history.js`) is uploaded as the pages artifact.
4.  The `deploy` job deploys this artifact to the `gh-pages` branch.

**Capturing Failures:**

The `bsan-script/src/commands.rs` script wraps each benchmarked command in a shell to redirect `stdout` and `stderr` to temporary files. If `hyperfine` reports a non-zero exit code for a command, the script reads these temporary files and injects their content into the final JSON result file.

### Frontend Features (`bsan-script/bench/`)

The benchmark page (`index.html`) is a static site that uses JavaScript (`index.js`) and Vega-Lite to render interactive charts and tables.

*   **Dark Mode:** The UI supports a light/dark mode toggle, with the preference saved in `localStorage`.
*   **Tool Selection:** Tools can be selected for display using a group of checkboxes. The performance outlier is highlighted with a distinct style.
*   **Chart Readability:** Charts are responsive and use appropriate scaling (linear or log) to enhance readability.
*   **Agreement Table:** This table shows the pass/fail status for each tool on the selected benchmark. For failed runs, a "Show" button opens a modal displaying the captured `stdout` and `stderr`.
*   **Benchmark History:** This table shows a performance comparison for the selected benchmark between the two most recent commits on the `main` branch, displaying the percentage delta in median execution time.
*   **Bug Fixes:** The script that prepares the data (`prepare-data.js`) now only processes the latest benchmark run directory, preventing incomplete or old runs from corrupting the data for the current view.
